Module directory

39 locked modules

Every module is specified as a set of numbered "micros" — discrete, individually implementable behaviours catalogued in a ledger before any of them are written. The counts below are read from that ledger. The full ledger spans 1,823 catalogued micros across 54 module keys, of which 1,023 are implemented in code today; the 39 locked modules shown here account for 1,706 of those rows and 984 of the implementations. The remainder are specified, redirected, held for review, or explicitly retired.

The distinction is easy to abuse and worth being exact about. "1,800 features" is a number that would fit on a résumé; 1,023 implemented is the number that survives someone opening the ledger. Both are on this page for that reason.

Modules with catalogued detail expand. The capabilities listed inside are the ones the generated micro audit marks as built — not the full catalogue, and not the roadmap.

Risk is the largest category on every measure — nine modules, 42% of the catalogued surface of the locked set, and more code than strategy, intelligence and execution combined. That is not an accident of counting; it is where I think the difficulty in this problem actually lives.

Current status

Profit Pilot is a working trading system, running continuously against a live brokerage API with real market data. It is in an independent testing stage ahead of public release — live capital is gated at the configuration layer by allow_live_trading: false while the five-layer test stack does its work.
