Verification

Five layers of testing, before anything reaches a broker

Five independent layers, each catching a failure the others miss.

Layer one

Historical backtesting

Every sleeve runs against historical bars through the same event bus the live engine uses — identical code path, not a parallel research implementation. Costs modeled, with an explicit survivorship-bias notice when the dataset holds only listed symbols.

Layer two

Deterministic blind replay

Any recorded session replays bar for bar and must reproduce a byte-identical event sequence. A bug from three weeks ago becomes reproducible on demand. Runs in CI.

Layer three

Out-of-sample gating

Challengers are scored outside their fitting window. Survivors advance to a fractional canary, never straight to full size, behind a significance threshold, a cooldown and a per-day cap.

Layer four

Monte Carlo & synthetic scenarios

The Ghost engine generates conditions the historical record does not contain; the Stress Lab pushes the portfolio through constructed shocks. A result is judged on its range, not its one lucky history.

Layer five

Live forward testing

Continuous paper trading against a live brokerage API — real quotes, real routing, real fill reconciliation. Forward testing is the only layer that cannot be overfitted, because the data has not been written yet. A fail-closed kill switch halts on any broker mismatch.

Self-Improvement Control Room. The loop currently reads dormant — 0 promotions, 1 of 4 stages reached. Live production console. Account balances and position values redacted; the account is a paper account.
WHAT THE DORMANT STATE ACTUALLY DEMONSTRATES. The surface explains itself on screen: "The self-improvement loop only acts once Calibration has measured real expectancy from live (post-market-open) bars. Until the engine processes real fills, these readouts stay empty rather than showing zeros as if a tuning cycle had run. No synthetic verdicts are shown." A self-modifying system that refuses to render progress it has not made is the correct behaviour. An empty readout that states why it is empty is more informative than a populated one without a source.

Underneath all five: an append-only decision ledger. The parameter state at any past moment is reconstructible.

Where this goes from here

The path to live

Four stages between forward testing and live capital. Each has a completion test.

01
Walk-forward validation

Rolling out-of-sample evaluation across historical data. Every component exists; the remaining work is orchestration over them.

02
Sim-to-live fidelity

Quantify and close the gap between modelled and actual fills, so simulated results become informative rather than aspirational.

03
Per-sleeve expectancy

Measure the six sleeves independently rather than in aggregate, so capital concentrates where it is earned.

04
Live deployment

Arming the live-trading ladder behind the same risk spine, at fractional size first.

Every stage produces the number that decides the next. Going live is a configuration change behind a risk spine that already governs every order — not a rewrite.
What's next

Where it goes from here

Profit Pilot is in its first full testing year. The platform is built and running; the work now is deepening the research layer around it.

Walk-forward validation

Rolling out-of-sample evaluation across historical data. Tuning, backtest and challenger evaluation already exist as components — this is the orchestration layer that chains them into a continuous rolling protocol.

Execution-model refinement

Tightening the fill model so simulated execution tracks live execution more closely — queue position, partial fills under stress, and market impact.

Per-sleeve attribution

Measuring all six sleeves independently rather than in aggregate, so capital concentrates in the ones earning their risk budget.

Broader universe

The live symbol set is currently capped by the market-data plan. Lifting that cap widens the opportunity set the allocator can select from.
